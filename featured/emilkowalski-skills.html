🤔 為什麼需要這個？

你有沒有遇過這種情況——設計師交了一張超美的 Figma 稿，但前端工程師做出來的東西總是差那麼一點？動畫不對、間距不對、顏色不對，來回修改三次還是不滿意。

問題不在於誰的能力不夠，而是設計和工程之間缺少一座橋樑。設計師用的是視覺語言，工程師用的是程式語言，兩者之間的翻譯成本太高了。

Emil Kowalski（前 Vercel 設計師、Sonner、Vaul 等知名開源元件庫的作者）做了一件事：把設計和工程的知識整理成一個統一的技能庫，讓兩邊的人都能用同一套語言溝通。

📦 裡面有什麼？

Skills 專案不是一個元件庫，也不是一個框架。它是一份結構化的知識庫，涵蓋設計師和工程師都該知道的技能：

💡 跟其他設計資源有什麼不同？

網路上不缺設計資源，但 Skills 有三個獨特之處：

1️⃣ 實戰導向，不是教科書
每一個技能都是 Emil 在 Vercel、Rauno 等頂尖團隊實際工作中的經驗總結。不是「按鈕應該是藍色」這種空話，而是「在深色背景下，按鈕的對比度至少要 4.5:1，否則在手機螢幕上看不清楚」這種具體指導。
2️⃣ 設計和工程放在一起
傳統的做法是設計指南和工程規範分開寫，結果兩邊各說各話。Skills 把它們整合在一起——同一個技能條目裡，設計師看到的是視覺原則，工程師看到的是實作建議，大家用同一個框架思考。
3️⃣ AI Agent 可以直接使用
Skills 的結構化格式讓 AI Agent 能夠直接讀取和應用。你對 Claude Code 說「幫我做一個無障礙的下拉選單」，它就能從 Skills 裡找到對應的指導原則，確保做出來的東西符合最佳實踐。

🚀 怎麼用？

1

瀏覽 GitHub 倉庫

到 github.com/emilkowalski/skills 瀏覽所有技能條目。每個條目都有清晰的標題、說明和範例。

2

在專案中引用

把需要的技能條目複製到你的專案文件中，或直接在 AI Agent 的 prompt 中引用。例如：

請參考 Skills 的動畫原則，幫我設計一個 modal 彈窗的開關動畫

3

設計師和工程師同步

讓設計團隊和工程團隊都讀同一份 Skills，建立共同語言。從此設計評審不再雞同鴨講。

💬 常見問題

Q: 適合什麼人用？
A: 前端工程師、UI/UX 設計師、產品經理、一人公司老闆——只要你的工作涉及「把設計變成產品」，都適用。

Q: 跟 Shadcn UI 之類的元件庫有什麼不同？
A: 元件庫給你現成的程式碼，Skills 給你背後的設計原則。知道「為什麼」比知道「怎麼做」更重要。

Q: 可以用在商業專案嗎？
A: 可以。MIT 授權允許商用，不需要付費。

Q: AI Agent 怎麼使用？
A: 把 Skills 的內容作為 context 丟給你的 AI Agent（Claude Code、Hermes、Cursor 等），它就能根據這些原則來設計和實作。
